# Commerce Insight 实施计划

> **实现状态（2026-11-02）**：本文是**计划文档**，多数任务（Medusa 应用骨架、PostgreSQL、真实支付/分析接入、Playwright E2E 等）尚未落地。当前实现范围见 [FACT_CARD.md](../../FACT_CARD.md)。

## 概览

使用 Medusa v2 应用脚手架与 Next.js Storefront，交付中文跨境电商演示和产品分析闭环。计划按“发现—决策—转化—实验—复盘”纵向推进，并把真实外部服务都设计为可选适配器。

## 架构决策

- 使用官方应用脚手架而非复制 Medusa 核心仓库，并固定生成器/依赖版本。
- 商业数据以 Medusa 为权威来源；分析和实验扩展通过清晰模块边界接入。
- 产品事件先可靠写入项目内存储，PostHog 是可选异步同步目标。
- 真实模型、PostHog 和支付均不作为本地演示前提；支付始终为明确标注的模拟流程。

## 阶段一：基础与样例业务

### 任务 1：生成并固定 Medusa 应用骨架

**描述：** 使用官方脚手架建立后端和 Storefront，记录版本、许可证与生成方式，并完成中文品牌替换。

**验收标准：**
- [ ] `UPSTREAM.md` 记录生成命令、版本、上游仓库和许可证。
- [ ] 后端、Storefront 和 PostgreSQL 可本地启动。
- [ ] 主界面使用 Commerce Insight 中文品牌，不保留模板品牌。

**验证：** 安装依赖、数据库迁移、后端健康检查、Storefront 生产构建。  
**依赖：** 无。  
**可能涉及：** 工作区配置、后端/前端包、`LICENSE`、`UPSTREAM.md`。  
**范围：** M。

### 任务 2：跨境商品与市场种子

**描述：** 建立可重复的商品、区域、货币、库存、配送选项和中文评论种子数据。

**验收标准：**
- [ ] 至少三个类目和两个市场具有完整图片、价格、库存和配送数据。
- [ ] 种子执行幂等，数据明确标识为演示数据。
- [ ] 商品覆盖正常、低库存、售罄和不同配送时效场景。

**验证：** 种子两次；API 查询快照；数据完整性测试。  
**依赖：** 任务 1。  
**可能涉及：** 种子脚本、商品夹具、图片资产清单、数据测试。  
**范围：** M。

### 任务 3：到手价与配送规则

**描述：** 实现确定性的商品价、模拟税费、配送费、到手价和预计送达计算。

**验收标准：**
- [ ] 相同输入始终得到相同结果，金额使用安全的最小货币单位。
- [ ] 不支持的市场、售罄和缺少配送选项有明确响应。
- [ ] 计算说明可直接用于商品详情展示。

**验证：** 表驱动单元测试；API 集成测试；边界金额测试。  
**依赖：** 任务 2。  
**可能涉及：** 后端模块、规则配置、Store API 路由、测试。  
**范围：** M。

## 检查点：基础

- [ ] 后端、Storefront、数据库和种子数据一键启动。
- [ ] 多市场商品与到手价可通过 API 验证。
- [ ] 生产构建通过且上游来源清楚。

## 阶段二：发现与决策

### 任务 4：中文商品发现闭环

**描述：** 实现市场切换、搜索、类目、价格、配送筛选、排序和分页，并保持 URL 可分享状态。

**验收标准：**
- [ ] 筛选组合正确影响结果且刷新后保留。
- [ ] 列表显示市场货币、到手价预估和配送承诺。
- [ ] 加载、空结果、错误和售罄状态完整。

**验证：** 查询参数单元测试；API/页面集成测试；Playwright 搜索筛选路径。  
**依赖：** 任务 3。  
**可能涉及：** 发现服务、搜索路由、列表组件、筛选组件、测试。  
**范围：** M。

### 任务 5：商品详情与评论摘要

**描述：** 完成商品详情、到手价拆分、预计送达、评论列表和真实/演示 AI 摘要。

**验收标准：**
- [ ] 详情优先展示最终金额、时效、库存和费用解释。
- [ ] 无模型密钥时展示标注的种子摘要；真实模型结果标注生成时间。
- [ ] 摘要失败不阻塞原始评论和加购。

**验证：** 摘要网关单元测试；详情 API 集成测试；Playwright 详情路径。  
**依赖：** 任务 3、4。  
**可能涉及：** 详情页、摘要服务/API、评论组件、测试夹具。  
**范围：** M。

### 任务 6：购物车到模拟订单闭环

**描述：** 打通加购、数量、地址、配送、模拟支付、订单确认和订单查询。

**验收标准：**
- [ ] 价格和库存由服务端重新校验。
- [ ] 支付和确认页面持续显示“演示环境，不会扣款”。
- [ ] 库存变化、地址无效和订单创建失败可恢复。

**验证：** 购物车/订单集成测试；Playwright 完整购买路径；失败场景测试。  
**依赖：** 任务 4、5。  
**可能涉及：** 购物车组件、结算页面、Medusa 工作流/路由、订单页、测试。  
**范围：** M。

## 检查点：用户主路径

- [ ] 用户可从发现页完成一次模拟订单。
- [ ] 多市场价格、库存和配送状态一致。
- [ ] 桌面与移动视口的主路径通过 E2E。

## 阶段三：分析与实验

### 任务 7：统一事件模型与隐私清洗

**描述：** 定义曝光、搜索、点击、加购、开始结算和下单事件，写入项目内存储并清洗敏感属性。

**验收标准：**
- [ ] 事件名、触发点、属性和指标口径写入埋点字典。
- [ ] 重试通过事件 ID 去重，不采集地址正文或支付信息。
- [ ] 事件写入失败不阻塞购物路径。

**验证：** 属性 schema 单元测试；去重/失败集成测试；E2E 事件断言。  
**依赖：** 任务 4、6。  
**可能涉及：** 分析模块、事件 schema/API、埋点字典、测试。  
**范围：** M。

### 任务 8：PostHog 可选适配器

**描述：** 在配置密钥且用户未关闭分析时，将统一事件异步同步到 PostHog。

**验收标准：**
- [ ] 未配置时不加载或调用 PostHog。
- [ ] 配置后事件名和属性与本地字典一致。
- [ ] 网络失败可观察但不影响主流程，关闭开关即时生效。

**验证：** 适配器 mock 测试；禁用/失败集成测试；浏览器网络检查。  
**依赖：** 任务 7。  
**可能涉及：** PostHog provider、服务端适配器、隐私设置、测试。  
**范围：** M。

### 任务 9：稳定实验分组与排序策略

**描述：** 将用户稳定分配到普通排序或高性价比排序，并允许 PostHog Feature Flag 覆盖。

**验收标准：**
- [ ] 同一匿名/登录用户跨会话保持实验组。
- [ ] 高性价比分数仅使用记录在文档中的可解释字段。
- [ ] 曝光和转化事件包含实验名、版本和分组。

**验证：** 分组稳定性和分布单元测试；排序快照；Flag 覆盖集成测试。  
**依赖：** 任务 4、7、8。  
**可能涉及：** 实验服务、排序策略、Cookie/用户属性、测试。  
**范围：** M。

### 任务 10：漏斗与实验看板

**描述：** 聚合 CTR、详情到加购率、结算完成率和分组差异，展示样本量和数据来源。

**验收标准：**
- [ ] 指标公式与埋点字典一致，处理零分母和重复事件。
- [ ] 可按时间、市场和实验组筛选。
- [ ] 演示数据、小样本和外部 PostHog 数据有明确标签。

**验证：** 固定事件集指标测试；看板 API 集成测试；Playwright 看板筛选。  
**依赖：** 任务 7、9。  
**可能涉及：** 聚合服务、看板 API/页面、图表组件、测试。  
**范围：** M。

## 检查点：分析闭环

- [ ] 一次购买路径生成完整且无敏感信息的事件链。
- [ ] 两个实验组稳定且指标可复算。
- [ ] 无 PostHog 配置时看板仍可完整演示。

**验证：** Playwright 多视口；自动可访问性扫描；人工视觉检查。

## 完成检查点

- [ ] 所有自动化测试和生产构建通过。
- [ ] 无外部密钥时发现、下单、漏斗和实验可完整演示。
- [ ] 产品文档与工程实现、事件和指标口径一致。
- [ ] Git 历史清楚，准备创建远程仓库并推送。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Medusa 生成器或 API 变化 | 高 | 固定版本，第一任务验证完整构建 |
| 多进程本地环境复杂 | 中 | 统一工作区脚本、Docker Compose 和健康检查 |
| 分析事件重复或口径漂移 | 高 | 类型化 schema、事件 ID、固定事件集回归测试 |
| 演示数据被误当真实结果 | 高 | UI、README 和产品文档持续标注 |
| 外部 PostHog/模型不可用 | 中 | 可选适配器、本地事件存储和种子摘要 |

## 开放问题

无；当前范围与关键取舍已经确认。

# Commerce Insight 设计说明

日期：2026-10-23  
状态：待用户书面复核

## 1. 项目定位

Commerce Insight 是面向小型跨境电商场景的中文商品发现与转化优化系统。用户可以完成“发现商品—查看详情—加购—结算—模拟支付—订单确认”，产品团队可以观察漏斗并比较普通排序和高性价比排序实验。

本项目面向产品经理求职展示。除可运行产品外，还交付用户研究模板、竞品分析、PRD、埋点字典、指标口径、实验方案和迭代复盘。

## 2. 上游与个人贡献边界

- 使用 Medusa v2 应用脚手架提供商品、价格、库存、购物车和订单等电商领域能力，不复制 Medusa 框架核心仓库。
- 使用 PostHog JavaScript SDK 接入产品分析、Feature Flag 和实验；不复制或自托管 PostHog 主仓库。
- 遵守使用到的 Medusa 与 PostHog SDK 许可证，并保留依赖声明。
- 个人核心实现包括跨境商品发现体验、市场和到手价表达、AI 评论摘要、中文商城界面、事件模型、漏斗看板、实验分组和产品文档。
- README 必须列出上游能力、个人实现和演示数据边界。

## 3. 用户、问题与成功标准

目标用户是希望购买海外小众商品、但担心价格不透明和决策成本高的年轻消费者。核心问题是商品难发现、到手价与配送信息分散、评论阅读成本高。

首版成功标准：

1. 用户可以切换市场，通过搜索、类目、价格和配送筛选发现商品。
2. 商品详情清楚展示商品价、预计税费、配送费、到手价和预计送达时间。
3. 用户可以查看明确标注为 AI 生成或演示数据的评论摘要。
4. 用户可以完成加购、地址、配送、模拟支付和订单确认。
5. 系统记录曝光、搜索、点击、加购、开始结算、下单完成等关键事件。
6. 产品看板展示搜索到详情 CTR、详情到加购率、结算完成率和主要流失步骤。
7. Feature Flag 将用户稳定分配到普通排序或高性价比排序，并展示分组结果。

## 4. 首版范围

### 包含

- 简体中文跨境商城和响应式布局。
- 多市场选择、类目、搜索、价格和配送筛选。
- 商品卡片、详情页、到手价拆分和预计送达。
- AI 评论摘要；无模型密钥时使用明确标注的种子摘要。
- 购物车、地址、配送、模拟支付、订单确认和订单查询。
- PostHog 可选接入、项目内事件记录、漏斗看板和 Feature Flag 实验。
- 普通排序与高性价比排序的 A/B 对比。
- 研究计划、访谈提纲、问卷、用户画像、用户旅程、竞品分析、PRD、优先级、埋点字典和复盘模板。

### 不包含

- 真实支付、退款、关税申报和物流商接口。
- 多商户结算、卖家后台和复杂促销引擎。
- 生产级个性化推荐模型训练。
- PostHog 私有化部署。
- 伪造真实用户访谈或真实上线增长结果；未执行的研究和实验必须标记为计划或模拟。

## 5. 架构与组件

- `storefront`：Next.js 中文商城，负责发现、详情、购物车、结算、订单和产品看板界面。
- `medusa-backend`：Medusa v2 应用，负责商品、区域、价格、库存、购物车和订单。
- `discovery`：组合市场、搜索、类目、价格、配送和实验排序参数。
- `landed-cost`：以确定性规则计算商品价、模拟税费、配送费和到手价，并显示计算说明。
- `review-summary`：调用 OpenAI 兼容 API 或返回标注为演示数据的种子摘要。
- `analytics`：定义统一事件模型，同时写入项目内事件存储；配置 PostHog 时再同步 PostHog。
- `experiments`：生成稳定分组并控制排序策略；PostHog Feature Flag 可覆盖本地分组。
- `insight-dashboard`：聚合漏斗和实验指标，保证无 PostHog Key 时也可演示。
- `database`：PostgreSQL 保存 Medusa 业务数据和项目扩展的事件、实验与摘要数据。

## 6. 核心数据流

1. 用户进入发现页，系统确定市场与实验分组。
2. 商品列表按筛选和分组策略返回，同时记录曝光与搜索事件。
3. 用户进入详情页，系统计算并展示到手价和配送区间，记录点击事件。
4. 评论摘要服务返回真实模型结果或显式标注的演示摘要。
5. 用户加购并完成地址、配送和模拟支付，Medusa 创建订单。
6. 分析层记录关键事件；若配置 PostHog，则异步同步相同事件名和属性。
7. 产品看板按时间、市场和实验组计算漏斗，展示样本量和模拟数据标识。

## 7. 指标与实验

主要指标：

- 搜索到详情点击率 = 搜索后产生的商品详情点击用户数 / 产生搜索结果的用户数。
- 详情到加购率 = 加购用户数 / 商品详情访问用户数。
- 结算完成率 = 下单成功用户数 / 开始结算用户数。
- 核心步骤流失率 = 1 - 下一步骤用户数 / 当前步骤用户数。

实验对比“普通相关性排序”和“高性价比排序”。高性价比分数仅使用可解释字段，如折扣、到手价、评分和配送时效。首版只验证埋点、分组和分析闭环，不把模拟样本结论描述为真实业务增长。

## 8. 界面设计

界面为简体中文，采用温暖的编辑式电商风格：米白背景、深棕正文和克制的橙色操作色。发现页强调大图、到手价与配送承诺；详情页优先回答“最终多少钱、多久送达、为什么值得买”；产品看板保持同一品牌但提高信息密度。

移动端优先保证发现、详情、加购和结算；桌面端提供更完整的筛选、价格拆分和指标对比。

## 9. 异常、安全与隐私

- 所有价格、库存、地区和订单状态在服务端再次校验。
- 模拟支付页面和订单记录持续显示“演示环境，不会产生真实扣款”。
- AI 摘要失败时回退到原始评论或标注的种子摘要，不阻塞下单。
- 分析 SDK 默认关闭；只有环境变量配置后启用，并提供用户可见的关闭开关。
- 不采集支付凭据、精确地址正文或评论自由文本到 PostHog。
- 事件上报失败不阻塞购物流程；本地事件记录和外部同步分别记录状态。

## 10. 测试与验收

- 单元测试：到手价、预计送达、实验分组、排序、指标计算和事件属性清洗。
- 集成测试：Medusa 商品查询、购物车、模拟订单、事件写入和 PostHog 适配器失败路径。
- Playwright：发现、筛选、详情、加购、结算、订单确认和产品看板。
- 分析校验：事件去重、漏斗口径、实验组稳定性、零分母和小样本提示。
- CI：格式检查、lint、类型检查、单元/集成测试和生产构建。
- 验收基线：新机器按 README 可启动数据库、后端、前端和种子数据；无 PostHog Key 和模型 Key 时仍可走完整演示。
